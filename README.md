# Corevia 약속계획

기존 납품 약속과 신규 입찰을 연결하는 AI 운영 시스템.

- 대회 업무는 W05 대형 수주와 기존 고객 약속입니다.
- 종합 현황에서 공급 여력과 다음 결정을 확인합니다. 고객·계약, 생산계획, 시나리오 분석, 검수·승인 화면에서 근거와 후속 작업을 확인할 수 있습니다. 시나리오 분석의 가정값은 업무 기록과 승인에 반영되지 않습니다.
- Node.js 22 이상에서 처음 한 번 `npm ci`를 실행하세요. 이후 프로젝트 루트에서 `npm run dev`를 실행하고 터미널에 표시된 주소를 엽니다. 기본 포트는 3000이며, 사용 중이면 빈 포트를 자동으로 선택합니다.
- `npm run build`는 업무 화면의 정적 번들을 생성합니다. 로컬 서버는 앱 화면과 API를 제공하며, 참가자 자료 폴더는 웹으로 제공하지 않습니다.
- 코드 저장소는 https://github.com/sang-mil/AX_contest 입니다.

Gemini 회신 분석은 Node.js 개발 서버에서 실행합니다. 프로젝트 루트의 `.env.local`에 `GEMINI_API_KEY`를 입력한 뒤 `npm run dev`를 실행하세요. 새로 내려받은 저장소에서는 키를 입력하기 전에 `.git/info/exclude`에 `/.env.local`을 추가하고 `git check-ignore .env.local`로 확인하세요. 모델을 지정하려면 같은 파일에 `GEMINI_MODEL`을 추가하세요. 화면에서 대상 행을 고른 뒤 회신을 분석하고, 표시된 변경값과 원문 근거를 확인한 뒤 적용합니다.
- 정적 프런트는 AXHub lounge의 Corevia 약속계획에 배포합니다. 공개 AI 서버는 Cloudflare Workers의 `corevia-promise-plan-api`입니다.

공개 앱은 질문·회신 원문과 수치를 브라우저에서 처리하고 Worker에는 정해진 업무 코드만 보냅니다. Worker는 AXHub의 정확한 출처와 Turnstile의 호스트·기능을 검증하고 호출량을 제한합니다. `public/ai-config.mjs`의 주소와 Turnstile 사이트 키는 공개 설정입니다. `GEMINI_API_KEY`와 `TURNSTILE_SECRET`은 Cloudflare Worker의 Secret으로 관리합니다. 출처를 바꾸면 Worker 설정과 Turnstile 허용 도메인을 함께 바꿔야 합니다. 보안 검증은 `node scripts/check-worker-security.mjs`로 실행합니다.

## 합의한 업무 설계

영업 접수 → 생산관리·재무 검토 → 공급안 통합 → 부서 간 정합성 확인 → CEO·이사회 승인 → 제안서 제출 → 회신에 따른 재검토.

계산과 상태 전환은 규칙 기반으로 처리합니다. AI는 담당자의 피드백 해석, 수정안 제안, 영향 설명과 보고를 담당합니다. 담당자는 같은 버전의 공급안을 검수하고 수락·조건부 수락·보완 요청·거절을 결정합니다.

정상 완료는 필요한 부서 검토와 최종 승인을 받은 조건이 제안서에 반영되고, 모의 제출 결과와 다음 확인 작업이 기록된 상태입니다.

### C-201 모의 시연

1. 업무 개요에서 C-201을 선택해 상세 검증을 시작합니다. RFP의 연 예상량과 대시보드의 비교 물량은 참고하고, 영업 검수에 별도의 모의 바이어 회신을 기록합니다. 예시 입찰 마감일은 `2026-07-22`, 초도일은 `2026-08-02`, 분할 조건은 `일괄 납품`입니다. 확정 납품표에 `2026-08-02 PL-01 10000; 2026-08-02 PL-02 6000`을 넣고 확인 근거를 기록한 뒤 영업 검수를 수락합니다.
2. 생산계획에서 **확정 납품표와 대시보드 근거 불러오기**를 누르고 계산합니다. 기존 확정 공급·별도 예약을 먼저 차감하고 같은 주의 수출 출고 여력 16,000 EA를 두 품목이 함께 사용합니다. 세 부서 수락과 경영진 승인 후 제안서를 모의 제출합니다.
3. 물류 회신의 7월 27일 주간 기존 예약을 40,000에서 44,000 EA로 바꾸고 회신 근거도 갱신합니다. 재계산하면 더마 제안량이 6,000에서 2,000 EA로 감소하고 이전 승인이 해제됩니다. 확정 납품표와 일치하지 않아 승인도 차단됩니다.
4. 분할을 허용하는 새 모의 바이어 회신을 기록합니다. 더마 6,000 EA를 8월 9일로 옮겨 납품표를 다시 저장하고, 재계산한 버전을 검수·승인합니다. 새 영업 검수로 넘어가도 앞서 수정한 수출 예약은 유지됩니다.

대시보드의 재고·생산·물류는 시연용 모의 데이터입니다. 연결된 주간의 생산 입고일을 모를 경우 주 마지막 날에 가용하다고 가정합니다. 현재 상세 계산 단위는 품목별 주간 납품 한 건이며, 입찰 진행 상태는 한 브라우저에서 한 건을 활성 상태로 관리합니다.

## 대회 제공 환경 안내

아래는 대회에서 제공한 프로젝트 폴더 안내입니다.

이 폴더가 프로젝트 루트예요. 문제 자료와 내 프롬프트 기록 설정이 함께 들어 있어요.

## 시작하기
1. 이 폴더(이 README.md 가 있는 폴더)를 AI 도구에서 프로젝트(작업 공간)로 열어요. 하위 폴더가 아니라 **이 폴더**를 열어야 기록이 수집돼요.
2. 처음 열 때 한 번 승인해요.
   - Claude Code: 폴더 신뢰 창에서 신뢰를 골라요. 데스크톱 앱은 새 세션을 만들 때 이 폴더를 작업 폴더로 골라요.
   - Codex CLI: 「Hooks need review」 창에서 Trust all and continue.
   - Codex 데스크톱 앱: 창이 뜨지 않아요. 설정 > Hook > 프로젝트에서 제공 > 모두 신뢰.
   - Codex VS Code 확장: 창이 뜨지 않아요. Codex 패널 톱니바퀴 > Codex settings > Hooks > From Projects > Trust all.
   - Antigravity: 승인할 것이 없어요. 사이드바의 Create Project 에서 이 폴더를 골라 열어요.
   신뢰한 뒤에는 새 대화를 열어요. 이미 열려 있던 대화는 예전 설정을 계속 써요.
3. 테스트 프롬프트(예: 안녕하세요)를 보내고, 참가 페이지 「문제 풀이 환경 › 기록 연결 확인」의 최근 프롬프트에 그 문장이 보이는지 확인해요.
   AI 도구를 이 폴더를 받기 전부터 켜 두었다면 재시작해요(도구는 시작할 때 설정을 읽어요).

## 꼭 지켜 주세요
- 풀이부터 앱 개발까지 이 폴더에서 해요. 다른 폴더에서 나눈 대화는 수집되지 않아요.
- .claude · .codex · .agents 폴더와 .gitignore 는 지우거나 고치지 마세요. 참가 신청에 묶인 개인 기록 키가 들어 있어 다른 사람과 나누면 안 돼요.
- 소스코드를 zip 으로 낼 때는 이 세 폴더를 빼고 묶어요.
- 기록은 기기가 아니라 기록 키로 모여요. 다른 기기에서 작업하면 이 폴더를 그대로 옮기거나 그 기기에서 다시 내려받아요.
- 이 폴더는 Windows 용이에요. Mac 에서 작업하려면 Mac 용으로 다시 내려받아요.
- Windows 는 C:\axwar 처럼 짧은 경로에 풀어요. 깊은 폴더에 풀면 경로가 260자를 넘는 자료 파일이 빠져요.
- Codex 를 처음 열면 「Set up the Codex agent sandbox」 창이 떠요. 관리자 권한이 있으면 관리자 설정, 없으면 non-admin 을 골라요.
